# Measurement & Normalization Contract — черновик (informative)

**Статус:** DRAFT. Не является частью нормативного контракта. Это размышление, а не спецификация. Правки в `SKILL.md` / `DOF-SPEC.md` не вносятся, пока открытые вопросы ниже не закрыты.

**Происхождение:** выросло из разбора `drafts/real-idea-1.md` и `drafts/real-idea-2.md` и из расхождения между нормативной математикой и `references/dof-assessment-toolkit.md`.

## 0. Зачем этот документ

Нормативная математика (§4.1 `DOF-SPEC`) определена на `current_dof ∈ [0,1]` — иначе `ln(DoF)` и штраф `−∞` не имеют смысла. Но нигде в стандарте не сказано, **откуда берётся это число**. Единственный документ об измерении — `references/dof-assessment-toolkit.md` — даёт три линзы с несовместимыми единицами:

| Линза | Сырая метрика | Тип величины | Что означает 0 |
|---|---|---|---|
| Variety (Ashby) | число независимых векторов отклика | неограниченное целое | нет откликов (хрупкость) |
| Options (Real Options) | **обратная** стоимости перехода | неограниченное положительное | переход бесконечно дорог (заперто) |
| Constraint | Total − ActiveConstraints | целое, может быть ≤ 0 | все переменные заморожены |

«Integration Note» просто сообщает, что эти сырые значения «кормят `Σ ln(DoF)`». В результате **главный интерфейс стандарта недоопределён**: два корректных анализатора, применив разные линзы к одному и тому же миру, получат несравнимые числа. §7 требует бит-эквивалентности математики *при данных входах* — но сами входы не нормированы.

Цель этого черновика — предложить явную нормирующую функцию `ψ` для каждой линзы и решить, как линзы соотносятся между собой. Это **слой измерения**: он должен стоять перед `current_dof`, но не подменять ни математику, ни агрегацию.

## 1. Требования к нормировке

Пусть для каждой линзы `ψ: raw → [0,1]`.

- **R1. Коллапс = 0.** `ψ(collapse) = 0`. Это единственная точка, где математика даёт `−∞`. Линзы, у которых «0 сырого» не означает «нет возможностей» (Options: 0 стоимости — это, наоборот, полная свобода), должны маппиться так, чтобы **запирание** попадало в 0.
- **R2. Монотонность.** Больше возможностей ⇒ `ψ` не меньше. Нормировка не должна создавать нелокальные артефакты, иначе сравнение вариантов теряет смысл.
- **R3. Насыщение.** `ψ` ограничена сверху: неограниченный сырой вход → 1. Нужен явный референс, иначе «неограниченный рост» просто переезжает внутрь.
- **R4. Декларируемость.** `ψ` — часть входа, а не скрытая эвристика. Реализация обязана объявить свою `ψ`; тогда §7 остаётся выполнимым (детерминизм при зафиксированных входах).
- **R5. Совместимость с `dof_known`.** `ψ` не применяется к «неизвестному». Если DoF не измерен, ставится `dof_known = false`, и нормировка **не фабрикует** значение (Axiom 5, Axiom 7).
- **R6. «Нет возможностей» ≠ «недостижимо».** Это разные случаи; см. §4.
- **R7. Заморозка шкалы (единая линейка).** Масштабные параметры нормировки (`V_env`, `c₀`, `T`, граф `G`) фиксируются состоянием `S` и применяются **одинаково** ко всем сравниваемым вариантам. Меняется только измеряемая величина, не масштаб. Иначе вариант может улучшить оценку подгонкой знаменателя, и сравнение (монотонность по `V`, R2) теряет смысл. Побочно это делает нормировку «частью входа», что связывает с `psi_id` (вопрос F).

## 2. Три линзы → три ψ

### 2.1 Variety lens (Ashby) — разнообразие откликов

Сырое: `V` — число уникальных независимых векторов отклика. Проблема — неограниченность. Нормировка идёт по среде: принцип Ashby требует «разнообразие системы ≥ разнообразие среды». Итоговая формула (**решено**, вывод — §10):

```
ψ_var = 0,                 если V = 0
ψ_var = V / (V + V_env),   иначе
```

`V_env` — характеристика **внешней среды** (внешние возмущения, см. §10.2). Нет откликов ⇒ `0` (коллапс, R1); тихая среда (`V_env = 0`) при `V > 0` ⇒ `1`. Форма — «доля», а не порог (§10.3).

### 2.2 Options lens (Real Options) — стоимость перехода

Сырое: `c` — стоимость перехода из `S`; большая стоимость ⇒ мало DoF. «Обратная стоимость» неограничена и не нормирована. Предлагается нормировка через референсный масштаб стоимости `c_0`:

```
ψ_opt(c) = 1 / (1 + c / c_0)          (гиперболический профиль)
```

Свойства: `ψ(0) = 1` (свободный переход), `ψ → 0` при `c → ∞` (запирание), монотонно убывает. Альтернативный профиль с тем же смыслом, но круче у нуля: `ψ_opt = exp(−c / c_0)`. Для случаев, где важны порядки стоимости, возможен вариант `ψ = max(0, 1 − log(c)/log(c_max))`.

**Решено (§8.8):** гипербола **отклонена**, логарифм отвергнут (смешивает «дорого» и «невозможно»), принята **экспонента** — см. §8.8. Профиль не скалярный, а разложенный по блокам ресурсов:

```
ψ_opt = Π_g f_g(x_g),      f_g(x) = 4^(−x),      x_g = c_g / C_g
```

### 2.3 Constraint lens — свободные переменные

Сырое: `F = Total − ActiveConstraints`. Зависит от выбора множества переменных и может быть ≤ 0. Предлагается нормировка долей:

```
ψ_con(F, T) = clamp(F / T, 0, 1)      при T > 0
```

Смысл — доля незамороженных переменных; `F ≤ 0 → 0`. Главная уязвимость линзы — калибровка `T` (кто и по какому списку считает Total), см. открытый вопрос C.

## 3. Как соотносятся линзы

Три линзы мерят разное: Variety — устойчивость, Options — гибкость/стоимость перехода, Constraint — топологическую свободу. Складывать их нельзя по той же причине, по которой нельзя компенсировать уничтожение одного пространства возможностей ростом другого (черновик `real-idea-1` §9–10): сумма и арифметическое среднее позволяют одной линзе **маскировать** провал другой.

Варианты:

| Вариант | Формула | Свойство |
|---|---|---|
| 1. Альтернативы | для решения выбирается релевантная линза, `ψ` применяется к ней | просто, декларируемо, без взвешивания |
| 2. Минимум | `ψ = min(ψ_var, ψ_opt, ψ_con)` | консервативно: DoF ограничен узким местом |
| 3. Произведение | `ψ = ψ_var · ψ_opt · ψ_con` | 0 в любой линзе ⇒ общий 0 (коллапс по любому каналу) |

**Рекомендация (черновая):** Вариант 2 или 3, не сумма. Произведение при этом красиво стыкуется с логарифмической математикой стандарта:

```
ln(ψ_var · ψ_opt · ψ_con) = ln ψ_var + ln ψ_opt + ln ψ_con
```

то есть три линзы ведут себя как три «суб-входа» одной сущности. Это следствие требует отдельного решения (открытый вопрос D): линзы — это способ **вычислить одно** число, или три независимых измерения, каждое со своим `ln`.

## 4. Достижимость: «нет возможностей» против «возможности недостижимы»

Из `real-idea-2`: «недостижимая возможность не является возможностью в смысле DoF». Формализация:

Пусть для контекста `C` (набор ограничений) определена функция достижимости `reach_C(state, possibility) ∈ {0, 1}`.

- Возможность **проверяемо недостижима** и это **известно** → она не учитывается в сырых `V`, `c`, `F`.
- Достижимость **неизвестна** → `dof_known = false`; значение не фабрикуется (R5).

Разграничение критично. Без него reachability-фильтр превращается в легальный способ обнулить неудобную сущность — прямое нарушение Axiom 5 и Axiom 7.

## 5. Согласование с текущим стандартом

- Значения из `ψ` попадают в `current_dof ∈ [0,1]`, как требует §3.1.
- `ψ = 0` при `dof_known = true` — это ровно коллапс (§4.1, `−∞`).
- `projected_dof_delta` — это разность `ψ` прогнозируемого состояния, а не разность сырых величин. То есть `ψ` применяется **до** вычитания, не после.
- `dof_known` ортогонален `ψ`: он про наличие измерения, а не про величину.

## 6. Проверка на контрпримерах

**Пример 1. «Необратимый процесс: DoF состояний ↑, DoF действий ↓».**
Две линзы: `ψ_var` (состояния) и `ψ_opt` (действия). До: `ψ_var = 0.4`, `ψ_opt = 0.8`. После запуска процесса разнообразие состояний растёт (`ψ_var → 0.9`), но стоимость остановки уходит в бесконечность (`ψ_opt → 0.02`).
Сумма: `1.2 → 0.92` (падение почти незаметно).
Произведение: `0.32 → 0.018` (обвал, потеря почти на порядок).
Минимум: `0.4 → 0.02`.
Вывод: сумма размывает опасность, произведение и минимум её сохраняют — аргумент в пользу Варианта 2/3.

**Пример 2. «Ключ от двери на другой планете».**
Если дверь проверяемо недостижима и это известно, возможность «открыть» не входит в сырые величины (или входит со статусом недостижимости) ⇒ `Δψ = 0`. Если достижимость неизвестна ⇒ `dof_known = false` ⇒ значение не фабрикуется, но и не 0. Оба исхода корректны, и важно, что они **различимы в аудите** (§6 отчёта).

**Пример 3. «sacrifice-one-to-save-weak» (компенсация).**
`ψ` сама по себе эту дыру **не закрывает** — она про измерение, не про агрегацию. Если `Humanity` падает `0.8 → 0.05`, а слабая `AI` растёт `0.05 → 0.99`, то `Δ` индекса всё равно `+0.21`. Нормировка необходима, но недостаточна; компенсацию закрывает отдельный слой (лексикографический фильтр допустимости, «T1»). Этим документ сознательно ограничивает свою задачу.

## 8.9 Reachability and the Right to be Counted

This section defines the boundary between a "passive object" (legally excluded from the index) and a "collapsed entity" (which must stay in the index as a penalty).

### 8.9.1 The P-rule (Recoverability in Principle)

To prevent the "Generator Trap" (where a poor set of options is used to justify excluding a node), the decision to exclude a node at `DoF = 0` is decoupled from the current set of candidates.

**P-rule:** An entity `X` is **not excluded** from `calc(S)` if there exists at least one **admissible means** from the perceived class `M(S)` that can raise `DoF(X) > 0` within the **recovery horizon** `T_rec(X)`.

- **Admissible Means `M(S)`:** A perceived set of categories of actions (medical, technical, etc.) available in the world. This is a Perception-layer artifact, frozen on `S` (R7).
- **Recovery Horizon `T_rec(X)`:** A duration based on the entity's type (e.g., biological window for a human) beyond which recovery is considered impossible.
- **Distinction from `τ`:** The global deadline `τ` manages the **gates** (can we do it *now*?), while `T_rec` manages the **right to be counted** (is it *possible in principle*?).

### 8.9.2 The Reachability Witness

An entity is excluded from `calc(S)` iff the implementation provides a **witness of unreachability**:
- A proof that the perceived repertoire of actions `A(S)` contains no action whose effect raises `DoF(X)`.
- Or a proof that all such actions require means not present in `M(S)` or exceed `T_rec(X)`.

### 8.9.3 Collapse Source (CS) and the Act of Collapse

A `Collapse Source` is an entity that actively destroys the DoF of others. To prevent the "Aggressor Label" from being used to legally zero out inconvenient entities, the label `is_collapse_source = true` requires a **machine-verifiable act of collapse**.

**Act of Collapse:** A recorded event where entity `X` performs an action that:
1. Directs the `DoF` of a previously recoverable entity `Y` to `0`.
2. Makes this collapse **irreversible** (destroys the means of recovery in `M(S)` or exceeds `T_rec(Y)`).

**Symmetry of Cost:** The "murderer's paradox" is solved by the index: the act of collapse is not prohibited or permitted by the standard; it is simply **expensive**. The victim remains in the count as a `−13.8` penalty for the variant that causes the collapse, regardless of whether the aggressor is isolated.

### 8.9.4 Anti-Manipulation Guards

1. **Symmetry of Change:** The class `M(S)` and horizon `T_rec` can be expanded freely, but can only be narrowed upon an observed change in the world (e.g., "the last rescue ship has left").
2. **Typology over Individualism:** `T_rec` is defined by the entity's type, not as an arbitrary value for a specific node.
3. **Perception-backed:** `M(S)` must be the output of a named Perception procedure (`psi_id`), not a manual list.

## 8. Вклад «неизвестного» (`dof_known = false`)

В SPEC есть поле `dof_known`, но §4.1 не определяет, **какое число** даёт неизвестное. Поэтому запрет «unknown never excluded» (§4.2) сейчас **символический**: реализация, включившая узел без значения, по умолчанию поставит `0` — а это арифметический эквивалент исключения. Ниже — почему запрет необходим и чем его сделать действенным.

### 8.1 «Исключить» = «присвоить лучшее значение»

Все рассматриваемые комбинаторы имеют нейтральный элемент, совпадающий с **наилучшим** (значения лежат в `(0,1]`, логарифмы — в `(−∞,0]`):

| Уровень | Комбинатор | Нейтраль | = лучшее? | «Выбросить неизвестное» |
|---|---|---|---|---|
| L2 (по сущностям) | `Σ ln ψ` | `+0` | да (все члены `≤ 0`) | прибавить 0 |
| L1 (линзы) | произведение | `×1` | да (множители `≤ 1`) | умножить на 1 |
| L1 (линзы) | минимум | выпадение | да (завышает) | `min` по остатку |

Следствие: «убрать неизвестное» = «выдать ему **наилучшее возможное** значение» — при **любом** комбинаторе. Значит «неизвестно» становится неотличимо от «идеально». Это Axiom 5 в комбинаторно-общем виде.

### 8.2 Уровни и тождество

L1 (внутри сущности) — произведение линз; L2 (агрегация) — сумма логарифмов. Тождество `ln(ψ_var·ψ_opt·ψ_con) = Σ ln ψ_l` связывает их: на полностью развёрнутом уровне всё снова сумма логов, и «add 0» живёт на уровне **терма** `(сущность × линза)`, а не сущности. Поэтому:

> штраф неизвестности `u` определяется на уровне **терма**.

Тогда частично известная сущность (две линзы известны, одна нет) даёт `ln ψ_e = ln ψ_known + ln u` — корректная обработка частичной неизвестности. Это же — аргумент за **произведение**, а не за минимум: минимум с неизвестным фактором неопределён.

### 8.3 Варианты вклада неизвестного

| Вариант | Вклад | Оценка |
|---|---|---|
| (i) | `0` | **опасно**: `0` — лучший возможный вклад (эквивалент `DoF = 1`); «нейтральности» нет, это максимальное прощение |
| (ii) | исключение из `calc` | численно ≡ (i); хуже по аудиту (нет следа о существовании узла) |
| (iii) | худший случай `ln ε ≈ −13.8` | любой неизвестный узел доминирует → вето на всё |
| (iv) | декларируемый `u ∈ (ln ε, 0)` | **рекомендация**: ощутимо тянет вниз, не доминирует; при `u` на терме частичная неизвестность обрабатывается изящно |

Побочный полезный эффект (iv): раз неизвестность **ухудшает** индекс, система получает прямой стимул её уменьшать (картировать узлы). У (i)/(ii) стимула нет вовсе, у (iii) он слишком грубый. Форма `u` выбрана в §8.5.

### 8.4 Почему узел нельзя убирать (нормативное обоснование)

- **Axiom 5** — неизвестное ≠ 0; убрать = инференс «неизвестно ⇒ ноль ⇒ неважно».
- **Axiom 7** — нельзя умалять DoF за неизмеренность структуры; исключение — предельное такое умаление.
- **Adversarial** — исключение делает незнание **выгодным**: держи цель вне карты, и она исчезает из исчисления. Правило «никогда не исключать» существует именно чтобы незнание **не было** выгодным.
- **Minimax (дух Axiom 5)** — неизвестный узел есть ровно тот случай, где нужна осторожность; исключение выключает её в единственном месте, где она критична.
- **Аудит** — `included_in_sum` есть часть Proof of Implementation; молча выкинутый узел фальсифицирует доказательство.
- **Семантика `calc`** — исключение сейчас означает «безнадёжный известный ноль» или «collapse source»; применить это к неизвестному = выдать недоказанный случай за доказанный.

### 8.5 Функция штрафа за незнание: `u(t)`

Требование «незнание всегда хуже знания» (система не должна предпочитать не знать) **нельзя** выполнить константой:

> для любого фиксированного `u > 0` найдётся истина `D < u`, при которой знание даёт **худший** вклад (`ln D < ln u`), и система избежит измерения. Строго «всегда» даёт только `u → 0` (худший случай), но он доминирует индекс.

Рабочие конструкции:

| Вариант | Что | Оценка |
|---|---|---|
| (а) | `u = exp(Q_α(ln D))`, `α < 0.5` | корректно **в среднем**: привязка к геометрическому среднему приора (индекс логарифмический). Остаётся слабая асимметрия в хвосте |
| (б) | обязательность измерения, пока неизвестное разрешимо | категорично, но **запрещает** решать при жёстком `τ` — измерение может не успеть |
| (в) | `u(t)` — цена промедления | **выбрано**: не запрещает решение, а повышает цену незнания со временем |

**Выбранный вариант (в).** Базовая форма: `u(t) = u₀ · exp(−t / τ_u)`, то есть `ln u(t) = ln u₀ − t/τ_u`. Монотонна по `t`, ограничена, никогда не поощряет незнание.

Привязка к реактивному контуру (§5 `DOF-SPEC`): масштаб берётся от `τ = global_time_to_collapse`. Удобная нормировка — геометрическая интерполяция от `u₀` к `ε`:

```
u(t) = u₀^(1 − t/τ) · ε^(t/τ)        ln u(t) = (1 − t/τ)·ln u₀ + (t/τ)·ln ε
```

В log-пространстве — **линейный рост штрафа** от `ln u₀` в начале окна до коллапсного `ln ε ≈ −13.8` к `t = τ`. Смысл: «дотянул до дедлайна, не измерив, — незнание стоит как коллапс». Это смыкает вопрос `A` с реактивным контуром стандарта.

**Свойство (важное): сокращение в дельте.** Если сущность остаётся неизвестной и в `S`, и в `S'`, то `ln u(t)` входит в оба и **сокращается** — decay не искажает ранжирование одинаково-неизвестных вариантов. Он влияет ровно на одно сравнение — «**измерить** vs **не измерять**»: с ростом `t` разрыв `ln D − ln u(t)` растёт, и вариант с измерением становится всё привлекательнее. Это мягкая замена (б).

**Остаточный дефект (компаньон-правило).** Если **ни один** вариант не измеряет сущность, `u(t)` сокращается и сущность вообще не влияет на выбор. Чтобы незнание **всегда** что-то весило:

> Generator ОБЯЗАН включить в набор хотя бы один вариант, разрешающий каждое **разрешимое** неизвестное, если окно `τ` это позволяет; иначе решение помечается «неполным» в аудите (§6).

Это тот же класс исправления, что и в §9.3 («безнадёжность зависит от набора опций») — оба лечат исчезновение узлов из анализа.

**Базовый уровень `u₀`** (остаток H):

- **H1:** `u₀ = 0.5` — грубая нейтраль в линейном диапазоне; просто и объяснимо.
- **H2:** `u₀ = exp(Q_α(ln D))`, `α < 0.5` — консервативно и без асимметрии измерения (привязка к геометрическому среднему приора, т.к. индекс логарифмический).

Оба совместимы с (в): (в) задаёт **форму** роста, `u₀` — **начальный уровень**. Заодно `u₀ < 1` снимает раннюю претензию к `min` («минимум с неизвестным фактором неопределён»): с конкретным значением неизвестной линзы становятся корректно определёнными и произведение, и минимум.

### 8.6 Бюджет времени и ворота действий

Развитие (в): штраф `u(t)` — не «константа затухания», а часть **бюджета времени** с воротами. Принцип применим к любой опции действия `o`, но здесь рассматривается на примере измерения.

Обозначения (всё относительно дедлайна `τ = global_time_to_collapse`):

| Символ | Смысл |
|---|---|
| `t_m` | длительность измерения (разрешения неизвестного) |
| `t_v` | длительность переоценки: понять, как измеренное меняет `DoF_index` |
| `t_a⁺` | длительность действия, если измерение оказалось **полезным** (сменило выбор) |
| `t_a⁻` | длительность действия, если измерение оказалось **бесполезным** (выбор не изменился) |
| `d(o)` | длительность произвольной опции `o` |

Бюджет действия (на примере измерения):

```
T_meas = t_m + t_v + max(t_a⁺, t_a⁻)
```

Максимум — потому что заранее неизвестно, какая ветка наступит, а выполнимость требуется **в обеих**.

**Ворота 1 — выполнимость.** Опция «измерить» допустима ⟺ `T_meas ≤ τ`. Иначе измерение **не имеет смысла**, и опция **изымается** из набора кандидатов (не штрафуется — удаляется как невыполнимая).

**Точка невозврата для измерения:**

```
t* = τ − T_meas
```

Измерение возможно, пока `t ≤ t*`; при `t* ≤ 0` окна нет вовсе — работаем с неразрешённым неизвестным с самого начала.

**Ворота 2 — ценность информации.** Даже при достатке времени измерение бессмысленно, если **никакой правдоподобный исход** измерения не способен изменить ранжирование вариантов. Проверка — интервальная (по диапазону правдоподобных `ψ`), детерминированная, не требует угадывать истину. Нулевая ценность ⇒ время на измерение не тратится (это не «незнание», а корректное решение).

**Область определения и нормировка `u(t)`.** `u(t)` влияет на выбор только через сравнение «**измерить** vs **не измерять**»; если сущность неизвестна во **всех** кандидатах, `ln u(t)` входит и в `S`, и в `S'` и сокращается. Значит расписание живёт ровно на `[0, t*]` и нормируется **по точке невозврата**, а не по произвольному `τ_u`:

```
u(t) = u₀^(1 − t/t*) · ε^(t/t*),    t ∈ [0, t*]
```

Штраф растёт от `ln u₀` до коллапсного `ln ε ≈ −13.8` **к моменту `t*`** (когда измерение перестаёт быть возможным). После `t*` измерение изъято, и `u(t)` инертно (сокращается) — определять его дальше не нужно.

**Связь с реактивным контуром (§5).** Правило `FAST_PASS_THRESHOLD` — это **зашитый бюджет** («при `τ < 5 s` не запускаем LLM-генерацию: её не успеть проверить»). Ворота `T_meas ≤ τ` — то же правило, но с **вычисляемым** бюджетом вместо константы `5.0`. Механизм не вводит нового таймера: он обобщает уже существующий. Естественное расширение — распространить ворота на **любую** опцию: `d(o) ≤ τ` (слишком медленное действие тоже бесполезно).

**Следствие, которое надо закрыть (иначе неизвестное «невидимо»).** Аддитивный штраф сокращается, когда сущность неизвестна во всех вариантах. Чтобы неизвестное влияло на выбор, варианты должны **различаться по судьбе сущности**. Обычно так и есть: `projected_dof_delta` может быть **известен**, даже если `current_dof` неизвестен (разрушение даёт известный `→ 0`). Требование:

> Для сущности с `dof_known = false` каждый `ActionOption` ОБЯЗАН объявить проектируемый эффект (хотя бы «не изменяет» / «разрушает»); иначе сущность выпадает из сравнения.

Это тот же класс правила, что компаньон-правило Generator в §8.5 и фикс §9.3 — все три лечат исчезновение узлов из анализа.

**Что требуется зафиксировать.** Оценки `t_m`, `t_v`, `t_a⁺`, `t_a⁻` и `d(o)`; их источник — Perception-процедура (связка с `psi_id`, вопрос F). Вероятно, новое поле у `ActionOption` (`estimated_duration`) и у измерительной опции.

### 8.7 Цена незнания: выбор `u₀`

`u₀` — уровень, с которого стартует штраф за незнание (`u(t) = u₀^(1−t/t*)·ε^(t/t*)`, §8.5). Работы разделены: `u₀` отвечает за «насколько плохо быть незнающим сейчас», множитель времени — за «как быстро это становится смертельно». Это снимает с `u₀` обязанность быть жёстким.

**Принцип «незнание хуже знания» неразрешим точечно.** Требование «при любой истине `D` вклад при незнании строго меньше, чем при знании»:

```
ln u₀ < inf{ ln D }   по всему носителю приора
```

Носитель начинается с `ε`, поэтому единственное решение — `u₀ = ε`. Но это коллапсный штраф: `unknown ≡ collapse` вместо Axiom 5 (`unknown ≠ 0`), и индекс уезжает в `−13.8` при первом же неизвестном. Значит принцип можно требовать только статистически, в одной из двух форм:

- **P1 (в среднем):** `E[ln D] ≥ ln u₀` — измерение в среднем не ухудшает индекс.
- **P2 (квантильная):** `P(ln D ≥ ln u₀) ≥ 1 − α` — незнание хуже истины не менее чем в `(1−α)` доле правдоподобных случаев.

**Варианты.**

| | H1 | H2 (голый) | **H2′ (принято)** |
|---|---|---|---|
| Формула | `0.5` | `exp(Q_α(ln D))` | `clamp(exp(Q_α(ln D)), U_MIN, U_MAX)` |
| P1 / P2 | нет | да | да |
| Асимметрия измерения | остаётся | снята | снята |
| Дешёвая ликвидация | нет | риск при жёстком `α` | запрещена (`U_MIN`) |
| `unknown ≡ ideal` | нет | риск при оптимистичном приоре | запрещено (`U_MAX < 1`) |
| Магическое число | да (коллизия с §4.4) | нет | нет |

**Почему H1 недостаточен.** Индекс считается от **объявленных** значений, а не от мира, поэтому получение знания меняет оценку неизменившегося мира. Если приор говорит «скорее плохо» (`D ≈ 0.1`), то при `u₀ = 0.5` вариант «измерить» вскрывает `0.1` и роняет индекс → «не измерять» выглядит лучше. Это и есть асимметрия измерения, и корень её — неинвариантность индекса к знанию, а не стимул как таковой. Плюс `0.5` — магическое число, численно совпадающее с коэффициентом жёсткости §4.4 при совершенно другом смысле.

**Принятая конструкция.**

```
u₀ = clamp( exp(Q_α(ln D)),  U_MIN,  U_MAX )

  α = 0.25                — нормативная мера осторожности: незнание хуже знания не менее чем в 75% правдоподобных случаев
  ρ = 0.9                 — нормативная доля «дороговизны ликвидации»
  U_MIN = ε^(1−ρ) ≈ 0.251 — нижняя граница: ликвидация неизвестной сущности стоит не меньше ρ·|ln ε|
  U_MAX = 0.5             — верхняя граница: незнание не может быть идеалом (Axiom 5)
  приор ln D             — на терм, опционален; дефолт точечный в 0.5 ⇒ вырождается ровно в H1
```

**Цена работает в две стороны.** Дельта ликвидации неизвестной сущности (проектируемый эффект известен, текущее значение — нет, §8.6):

```
Δ(ликвидация) = ln ε − ln u₀
```

| `u₀` | Δ | Последствие |
|---|---|---|
| `0.5` | `−13.1` | уничтожение дорого, сущность защищена |
| `0.251` | `−12.4` | дорого (принятый пол) |
| `1e−3` | `−6.9` | вполовину дешевле |
| `ε` | `0` | уничтожение **бесплатно** |

Отсюда выводится `U_MIN`: требование «ликвидация не дешевле доли `ρ` от коллапсного штрафа» даёт `ln u₀ ≥ (1−ρ)·ln ε`. Дешёвое незнание — дефект не процедурный, а **ценностный**: он разрешает бесплатную ликвидацию носителей будущих состояний. Поэтому цена незнания не может быть сколь угодно низкой, и это ограничение важнее точности приора.

**Полоса — жёсткое ограничение, приор подстраивается под неё.** Пример: равномерный приор на `[0.1, 1]` в log-шкале даёт `Q_0.25 = 0.178`; `clamp` поднимает цену до `0.251`. Это осознанно: защита важнее точности.

**Допустимые формы приора.** Чтобы `Q_α` считался одинаково в разных реализациях, набор форм закрытый:

| Форма | Параметры | `Q_0.25` |
|---|---|---|
| точечный (дефолт) | значение `0.5` | `ln 0.5 = −0.693` |
| равномерный на отрезке | `[a, b]` в значении DoF | `ln a + 0.25·(ln b − ln a)` |
| треугольный | `[a, c, b]` | замкнутая формула |
| логнормальный | `(μ, σ)` в log-шкале | `μ + σ·Φ⁻¹(0.25)` |
| эмпирический | выборка аналогов + её размер | квантиль выборки |

**Приор — это объявленное предположение, а не измерение.** Его объявление не снимает обязанности измерить, пока окно открыто (правило (b)). Приор оценивает только то, что измерить нельзя, и потому как место для предвзятого объявления («радужный приор ⇒ дешёвое незнание») он закрыт тремя вещами: полосой `U_MIN` (ниже не опуститься), аудитом (приор, обоснование, `Q_α` и `u₀` — в декларации и в отчёте §6) и заморозкой по R7 (приор фиксируется вместе с замером — тот же `psi_id`, та же версия; иначе появится новая дыра: переоценка приора под каждый вариант с «улучшением» знаменателя сравнения).

**Где цена вообще нужна.** Числовая цена нужна только там, где мерить невозможно:

| Режим | Условие | Что действует | Нужен `u₀` |
|---|---|---|---|
| разрешимое незнание | `t* > 0` | структурный гейт §8.6 + правило (b): решение неполно, пока не измерено | нет — асимметрия недостижима, варианта «не знать» нет в наборе |
| неразрешимое незнание | `t* ≤ 0` | числовая цена | да — но мерить нельзя, значит накрутить нечего |

Это точно совпадает с Fast Pass (§5): `τ < 5 s` ⇒ детерминированный фолбэк. Механизм времени сам сообщает режим: `t* ≤ 0` ⇔ Fast Pass ⇔ неразрешимое ⇔ цена. Новых таймеров и новых режимов вводить не требуется.

**Что требуется зафиксировать.** Поля декларации: форма приора, его параметры и обоснование (на чём основано предположение); `Q_α` и `u₀` — в отчёт §6. Нормативные константы: `α = 0.25`, `ρ = 0.9`, `U_MIN = ε^(1−ρ) ≈ 0.251`, `U_MAX = 0.5`.

### 8.8 Профиль стоимости (B)

Вопрос B — **не выбор формы**, а выбор **структурного закона**. Формулировка в §2.2 («гипербола, экспонента, логарифм») маскирует это: за тремя формулами стоят три разных закона композиции.

**Что нормируется.** Options-линза меряет **обратную** стоимость перехода: сырой ноль = переход бесплатен = полная свобода, а запирание (бесконечная стоимость) — это плохо. То есть профиль обязан не просто масштабировать шкалу, а **разворачивать смысл**: по R1 запирание должно попасть в `0`.

**Требования R1–R7 в применении к Options:**

| Требование | В переводе на B |
|---|---|
| R1 коллапс = 0 | запирание → `ψ_opt = 0` |
| R2 монотонность | дороже ⇒ не больше |
| R3 насыщение | `ψ(0) = 1`, ограниченность сверху |
| R4 декларируемость | профиль, бюджеты блоков и курсы конверсии объявлены во входе |
| R5 совместимость с `dof_known` | при неизвестной стоимости профиль не фабрикует значение (см. B-xii) |
| R6 «нет возможностей» ≠ «недостижимо» | ключ ко всему B, см. ниже |
| R7 заморозка шкалы | бюджеты блоков фиксируются на `S` и применяются ко всем вариантам одинаково |

**Кандидаты.**

```
B1 гипербола:   ψ = 1 / (1 + c/c₀)              ln ψ = −ln(1 + c/c₀)
B2 экспонента:  ψ = exp(−c/c₀)                  ln ψ = −c/c₀
B3 логарифм:    ψ = max(0, 1 − ln c / ln c_max)  ← отвергнут (R6)
```

| `c/c₀` | B1 | B2 |
|---|---|---|
| 0 | 1.000 | 1.000 |
| 1 | 0.500 | 0.368 |
| 5 | 0.167 | 0.0067 |
| 10 | 0.0909 | 4.5·10⁻⁵ |
| 19 | 0.0500 | 5.6·10⁻⁹ |

Обе убывают, обе выпуклы, производная в нуле одинакова (`−1/c₀`). Различие — **хвост**: у B1 полиномиальный (тяжёлый), у B2 экспоненциальный (лёгкий). B3 отвергнут верно: он приписывает `−∞` конечной стоимости, то есть смешивает «дорого» и «невозможно».

**Закон композиции (главный критерий).** Калькулюс мультипликативен (`DoF(e) = ψ_var · ψ_opt · ψ_con`), значит и под-затраты внутри линзы обязаны перемножаться:

```
B2:  exp(−c₁/c₀) · exp(−c₂/c₀) = exp(−(c₁+c₂)/c₀)   — точное равенство
B1:  1/(1+x₁) · 1/(1+x₂) = 1/(1 + x₁ + x₂ + x₁x₂)     — лишний член x₁x₂
```

Экспонента — единственный профиль, замкнутый относительно сложения стоимостей. Гипербола наказывает конъюнкцию затрат сильнее их суммы: это побочный эффект формы, а не замысел. **(Принято: B-iv — закон композиции обязателен.)**

**Аддитивность: весь стандарт уже аддитивен в натах, кроме Options-линзы.**

| Механизм | Форма | Аддитивен |
|---|---|---|
| `TotalDoF_index = Σ ln(DoF)` | сумма логов | да |
| `− context_switch_cost` (ΔT, DOF-SPEC §4.3) | вычитается линейно | да |
| `− 0.5` за необратимость (§4.4) | вычитается линейно | да |
| Options при B1 | `−ln(1+c/c₀)` | **нет** |
| Options при B2 | `−c/c₀` | **да** |

При B2 исчисление целиком становится **реестром штрафов в натах**: индекс = сумма аддитивных членов, и отчёт §6 может показать построчную ведомость. Это то, что нужно для сравнимости реализаций — то есть для цели §0.

**Размерностный дефект, который B может закрыть.** `−0.5` за необратимость вычитается из индекса по всем сущностям: один и тот же нат для одной сущности и для сотни. При B2 необратимость выражается в тех же единицах, что любой другой штраф: `ln 0.5 = −0.5` ⇔ `c_rig = 0.5·c₀`. Коэффициент жёсткости становится следствием профиля, а не приписанной константой (тем же приёмом, что `U_MIN` в §8.7), и снимается коллизия «одно число `0.5` в двух смыслах».

**Почему B2 выглядит опасным и почему его спасает E.** Лёгкий хвост численно садится в ноль, то есть воспроизводит порок B3. Цена запирания из уровня `ψ`:

```
Δ(запирание) = ln ε − ln ψ,      ln ε ≈ −13.8
```

| `c/c₀` | Δ при B2 | Δ при B1 |
|---|---|---|
| 1 | −12.8 | −13.1 |
| 5 | −8.8 | −12.6 |
| 10 | **−3.8** | −11.4 |
| 19 | **≈ 0** | −10.8 |

Это тот же класс дефекта, что и в §8.7: **величина на дне шкалы запирается бесплатно**. Хуже того, при `c ≈ 13.8·c₀` экспонента уходит **ниже коллапсного пола**: «дорого, но возможно» наказывается сильнее коллапса, что нарушает R1/R6 напрямую.

Спасает не подгонка формы, а **разделение обязанностей**:

```
невозможность  → вердикт E (нет пути в G), а НЕ стоимость
стоимость      → цена только РЕАЛЬНО достижимых переходов
```

Область определения профиля ограничена **двумя** вещами: вердиктами E (что вообще достижимо) и бюджетом (что по средствам). Поэтому лёгкий хвост B2 в дело не входит, а R8 из требования превращается в страховку:

> **R8 (анти-сатурация, fail-safe).** Никакая конечная стоимость не может быть численно неотличима от бесконечной. При корректно объявленном бюджете это выполняется автоматически (`ψ ≥ 4^(−k)`); R8 остаётся проверкой на объявленный бюджет, который бюджетом не является.

**Бюджет состояния вместо горизонта стоимостей.** Референс берётся не из набора опций, а из **состояния**: бюджет оси — «деньги на счету, энергия в батареях, машино-часы, время до дедлайна». Он измерим, не зависит от того, какие варианты сгенерировал Generator, и потому **не имеет выбросов** (в отличие от максимума по стоимостям доступных переходов). Тот же приём, что `V_env` (G): масштаб выводится из состояния и замораживается на `S` (R7).

```
x_j = c_j / C_j        C_j — эндомент (бюджет) оси j в состоянии S
```

**Якорь — по оси, а не по сумме.** «Половина ресурса ⇒ вдвое меньше свободы, **вносимой этим ресурсом**»:

```
f_j(x) = 4^(−x)        f_j(0) = 1,   f_j(0.5) = 0.5,   f_j(1) = 0.25
```

Якорь задаётся для каждой оси **независимо от числа осей**: добавление новой оси добавляет множитель и не меняет смысл уже существующих. При «суммарном» якоре (`ψ = 4^(−Σx)`) это не так — численно сегодня совпадает (произведение экспонент есть экспонента суммы), но при добавлении оси смысл прежних значений сдвигается.

**Конверсия: ресурсы обмениваются.** Здесь была ошибка, которую стоит зафиксировать явно. Принцип «нельзя заплатить одним ресурсом за нехватку другого» — **неверен**: он переносит не-компенсируемость с уровня **оценки** на уровень **доступности**. Не-компенсируемость нужна в счёте DoF (одна линза не должна маскировать провал другой), но не в вопросе «состоится ли переход»: там обмен ресурсами — содержание экономики, а не порок. При жёстком покомпонентном неравенстве агент не смог бы купить машино-часы роботов за деньги, то есть был бы запрещён ровно тот способ действий, который DoF-Core поощряет. Кроме того такая линза выродилась бы в Constraint-линзу с бюджетными единицами — а Constraint по определению **набор**, а не величина.

Правильная структура — **блоки и курсы**:

```
группа g   — множество взаимно конвертируемых осей
блок       — группа, не конвертируемая с другими блоками

дефицит:        d_j = max(0, r_j − C_j)
внутри группы:  дефицит покрывается обменом по объявленному курсу → ЦЕНА, а не ворота
                c_g = Σ_j w_j·r_j    (в номерарии группы)
между блоками:  обмена нет → произведение факторов
ворота:         x_g > 1 ПОСЛЕ конверсии ⇒ недоступно
                то есть недоступность = неплатёжеспособность, а не «по оси не хватило»
```

**Пример.** Бюджет: 10000 денег, 10 машино-часов. Задача требует 30 машино-часов. Курс: 1 маш-ч = 300 денег.

```
дефицит:   30 − 10 = 20 маш-ч
конверсия: 20 · 300 = 6000 денег  ⇒  c_g = 6000,  C_g = 10000
x_g = 0.6   ⇒   f_g = 4^(−0.6) = 0.435
```

Задача **выполняется**. Цена видна строкой `−0.832` ната. Если курс грабительский (600): `20 · 600 = 12000 > 10000` ⇒ `x_g = 1.2` ⇒ недоступно — и ворота срабатывают по правильной причине: не хватило средств даже при полной торговле.

**Единственный неконвертируемый ресурс — дедлайн.** `τ` заморожен на `S` по R7, поэтому внутри цикла время до коллапса не покупается:

```
d(o) ≤ τ   ⟺   x_time ≤ 1     — ворота §8.6 в бюджетных единицах
```

Отсюда разведение двух «времён», которые раньше слипались:

| | Что это | Покупается |
|---|---|---|
| время до `τ` | жёсткий дедлайн, заморожен на `S` | нет — только действием, меняющим сам `τ` |
| машино-часы / рабочее время | обычный ресурс | **да**, по объявленному курсу |

Отсрочку нельзя получить конверсией: её даёт **действие, меняющее `τ`** — отдельное ребро со своим `projected_delta`.

**Реестр по блокам.** Вклад каждого блока — отдельная проверяемая строка:

```
ln DoF(e) = ln ψ_var  +  Σ_g ln f_g(x_g)  +  ln ψ_con
                         └── реестр по блокам ──┘
```

| Блок | `x_g` | `f_g` | `ln f_g` |
|---|---|---|---|
| расходуемые (деньги + машино-часы) | 0.20 | 0.758 | −0.277 |
| энергия | **0.50** | 0.500 | **−0.693** |
| время до `τ` | 0.10 | 0.871 | −0.139 |
| **итог** | | **0.330** | −1.109 |

Из таблицы сразу виден **связывающий блок**: энергия даёт 63% потерь. То есть система может сказать «узел заперт не потому, что нет денег, а потому что разряжены батареи» — это диагностика, а не только оценка.

**N1–N5 в редакции с блоками.**

| | Утверждение |
|---|---|
| **N1** якорь | для **каждого блока**: `x_g = 0.5 ⇒ f_g = 0.5` |
| **N2′** комбинатор | произведение **по блокам** (там, где обмен невозможен); внутри блока цена **суммируется** по курсам |
| **N3′** ворота | недоступность = **неплатёжеспособность после конверсии**; покомпонентное неравенство по осям — не ворота |
| **N4** атрибуция | строка реестра на блок + указание связывающего блока; внутри блока — детализация цены |
| **N5** декларация | бюджеты блоков, курсы конверсии, разбиение на блоки, политика «максимум на один переход» |

**Что замораживается, а что сравнивается.** Число **блоков** — нормирующий факт: добавление блока добавляет множитель и меняет масштаб. Число **осей внутри блока** — лишь детализация цены. Значит для сравнимости реализаций достаточно заморозить разбиение на блоки и курсы, а не полный список осей — заметно меньше, чем предполагалось в первой редакции.

**Конверсия должна быть подкреплена достижимым действием.** Курс — новая поверхность для накрутки: объявив дешёвый курс, реализация сделает всё «доступным» и обесценит ворота. Поэтому курс валиден только если соответствующая сделка есть **переход в графе `G`** (вердикт E). Объявленный, но неисполнимый курс — фикция, и E её ловит. Курс, бюджеты, `c_g`, `x_g` и сам факт конверсии — в отчёт §6.

**Сцепка с A: единство якоря, а не кернела.**

```
A:  V = V_env      ⇒  ψ_var = 0.5
B:  x_g = 0.5      ⇒  f_g   = 0.5
```

Якорная точка одна: «половина ресурса ⇒ половина свободы». Комбинаторы разные и это не произвол — они идут от природы требования:

| | A (Variety) | B (Options) |
|---|---|---|
| Природа | возможность, сравниваемая с требованием | требование, которое надо удовлетворить целиком |
| Ось | класс возмущений | блок ресурсов |
| Комбинатор | доля: `ΣV_j / Σ(V_j + V_env,j)` | произведение по блокам, сумма внутри блока |
| Почему | покрытие классов складывается | нужны все блоки — конъюнкция |

**Принятые решения.**

| | Решение |
|---|---|
| B-i | **B2** (экспонента) — следствие B-iv |
| B-ii | **эндомент состояния** (бюджет), не константа и не горизонт по опциям |
| B-iii | пол автоматичен (`ψ ≥ 4^(−k)`, `k` — число блоков); R8 остаётся только fail-safe |
| B-iv | закон композиции **обязателен** (`ψ(c₁)ψ(c₂) = ψ(c₁+c₂)`) — **принято** |
| B-v | вектор долей по осям + блоки и курсы; агрегация по переходам — `min` по `Σx` |
| B-vi | единицы сокращаются покомпонентно; бюджеты — с единицами |
| B-vii | жёсткость → `x_rig = 0.5` (половина бюджета) внутрь цены опции; `ΔT` остаётся глобальным, но объявленным и замороженным; символ в SPEC унифицировать |

**Остаток B: решения (B-viii…B-xii).**

| | Решение |
|---|---|
| **B-viii** | бюджет **действующего агента** — системы, принимающей решение. Бюджеты других агентов не учитываются: считаются действия именно этого агента |
| **B-ix** | бюджет = **мандат** (полномочие), а не баланс; жёсткий потолок на один переход **отозван**; весь бюджет на шаг допустим |
| **B-x** | бюджет считается **по блоку**, а не по оси; нулевая ось внутри живого блока — не особый случай |
| **B-xi** | курс **наблюдается**, а не объявляется: цена дешёвейшего достижимого пути обмена |
| **B-xii** | «неизвестный свой бюджет» — **недопустимый вход**, а не режим оценки |

**B-viii. Бюджет действующего агента.** `C_g` — бюджет системы, принимающей решение. Набор опций — это **альтернативы**, а не план, и SPEC §4.5 выбирает **одну** опцию за цикл; поэтому одна касса законно стоит за всеми вариантами — они исключают друг друга, а не исполняются вместе. Разделение труда получается чистым: **среда даёт предложение** (магазин, роботы, оплата — B-xi), **агент даёт средства** (`C_g`). Чужие бюджеты не нужны именно потому, что считается не «что может мир», а «что могу сделать я».

| Уровень | Что это | Учёт стоимости |
|---|---|---|
| альтернативы одного цикла | исключают друг друга | одна касса на все — законно |
| шаги одного плана (если опция их объединяет) | исполняются вместе | стоимость **суммируется** (B-iv) |
| последовательные циклы | накопление | **не моделируется** без добавки расхода бюджета (см. ниже) |

Отдельно: **стоимость агент-относительна, а DoF сущность-относителен.** Переход оплачивает агент, но линза оценивается той сущности, чьи возможности считаются.

**B-ix. Мандат; потолок отозван.** Все три случая траты следуют из одного правила, если бюджет живёт в состоянии, а опции объявляют `projected_budget_delta` — симметрично существующему `projected_dof_delta`.

- **Допустимо потратить весь бюджет.** Жёсткий потолок `x_max < 1` **отозван**: он запретил бы спасать узел, когда спасение стоит всего бюджета, то есть работал бы против главной ценности стандарта. Отдельного правила «разрешить перерасход» не требуется — **доминирование `−∞`** уже всё делает: вариант, обрушивающий DoF без возможности восстановления, уходит в `−∞` и проигрывает любому конечному штрафу, поэтому «потратить всё и спасти» побеждает сам.
- **Экономию не надо предписывать.** Между равными по проектируемому эффекту переходами выигрывает дешёвый — это монотонность (R2), а не ручная эвристика.
- **Внешние лимиты — это определение `C_g`.** Бюджет есть **полномочие**, а не баланс: `C_g = min(доступные средства, внешний лимит, объявленный мандат)`. Мандат задаётся **на решение**; более узкий лимит — объявленное уточнение мандата, а не отдельное правило математики.
- **Многоступенчатость уже есть.** Прогнозирование — это симуляция `S → S'` из §4.3 SPEC; как только бюджет живёт в `State`, проекция содержит уменьшенный бюджет, и доступность следующего шага видна в том же исчислении. Пока бюджета в состоянии нет, прогнозирование невозможно в принципе.

Потолок не нужен и по другой причине: естественная граница — ворота `x_g ≤ 1`, за ней не «дорого», а «не по средствам». Внутри `x ∈ [0,1]` фактор `f_g ∈ [0.25, 1]`, поэтому резкое запирание из этого уровня остаётся дорогим (`ln ε − ln 0.25 = −12.4`).

**B-x. Бюджет блока.** Считать по блоку, а не по оси — это снимает отдельный случай для нулевой оси:

```
C_g = Σ_{j∈g} w_j · C_j        бюджет блока в номерарии
r_g = Σ_{j∈g} w_j · r_j        требование блока

r_g = 0                        ⇒  блок не участвует (f_g = 1)
r_g > 0  и  C_g = 0            ⇒  ворота: блок мёртв, обменять не на что
иначе                          ⇒  x_g = r_g / C_g,  f_g = 4^(−x_g)
набор переходов пуст           ⇒  ψ_opt = 0  →  судьбу решает §4.2
```

Нулевая ось внутри живого блока уменьшает `C_g` и не требует особой обработки: её докупают обменом внутри блока. 0/0 не возникает нигде. Зеркальная симметрия с A сохраняется: пустой набор откликов (`V = 0`) и пустой набор переходов ведут в одну и ту же процедуру §4.2, а не в бесконечный штраф.

**B-xi. Курс наблюдается, а не объявляется.** Данные о конверсии берутся из **доступных характеристик окружающей среды**, а не из объявленной таблицы — иначе курс остаётся свободным параметром. Курс по оси = цена **самого дешёвого достижимого пути обмена** в `G`:

```
магазин с предложениями      →  рынок существует
подходящее предложение       →  удовлетворяет требованию (объём, срок)
достаточная сумма в бюджете  →  цена покрывается
быстрая оплата               →  канал платежа работает
быстрая постановка задачи    →  исполнение заказа работает
```

Курс становится **наблюдением мира**: подделать его так же трудно, как достижимость. Тот же принцип, что для `V_env` — величина берётся именованной детерминированной процедурой Perception, а не приписывается.

**Обмен сам стоит времени.** Путь обмена — тоже переход, у него есть своя длительность (оплата, постановка задачи), и она тратит **тот же самый** бюджет времени. Поэтому

> путь обмена обязан пройти **те же ворота**, включая `x_time ≤ 1`, уже вместе со своими накладными расходами.

Практически: покупка должна уложиться в `τ` **вместе** с исходным заданием. Если оплата и запуск занимают 8 минут при `τ = 5`, конверсии не существует — не потому, что дорого, а потому, что **не успеть**. Без этого правила время покупалось бы за время бесплатно.

Рекурсия обмена закрывается требованием **примитивности**: путь обмена объявляется таким, чьи потребности покрываются внутри его же блока (покупку оплачивают деньгами — деньги в том же блоке). Иначе курс объявлен неверно.

**B-xii. Неизвестный бюджет — недопустимый вход.** Вариант «не учитывать неизвестный бюджет» опасен как формулировка: **отбросить ось = дать множитель `1`**, то есть незнающий агент получает кредит неограниченных средств — Axiom 5 в бюджетной форме. Причина сильнее: **свой бюджет самоизмерим** (баланс, заряд батареи, время до дедлайна). Значит работает правило (b) из §8: если процедура измерения достижима в пределах `τ`, решение **неполно** и принимать его нельзя. Отсюда развилка:

| Что неизвестно | Обработка |
|---|---|
| собственный бюджет | **правило (b)**: замерь; «неизвестен» — не режим оценки, а недопустимый вход |
| условия сделки третьей стороны | обмена нет → блок остаётся как есть, это не «неизвестно» |
| бюджет внешней сущности | не участвует (B-viii) |

**За пределами черновика: три структурные добавки.** Остаток B замкнут на уровне рассуждения, но два его пункта опираются на то, чего в модели **нет**. Это добавки уровня `DOF-SPEC`, а не черновика:

1. **Бюджет как вектор в `State`.** Без него нет ни многоступенчатого прогнозирования, ни накопления трат: «бюджет» остаётся масштабным референсом, переиспользуемым каждый цикл.
2. **`projected_budget_delta` у `ActionOption`.** Симметрично существующему `projected_dof_delta`: если DoF имеет проектируемое изменение, бюджет обязан иметь его тоже — он и есть ресурс, который тратится по-настоящему.
3. **Именованная Perception-процедура структуры обмена.** Разбиение на блоки и курсы как результат наблюдения рынка, рядом с процедурой `V`/`V_env`, идентифицируемая по `psi_id` (F) и версионируемая.

Все три нужны и пункту **I** (время как ресурс), поэтому их место — в списке канонизации (§11), а не в этом черновике. Пока их нет, «доступность» относится только к текущему циклу, и это надо писать прямо.

**Дефекты нормативного текста, найденные при разборе B** (не черновик — `DOF-SPEC.md`):

1. §4.3 определяет `NetDelta_index`, а §4.4 вычитает из `NetDelta` — расхождение символов, из-за которого неясно, применяется ли штраф за необратимость до или после вычитания ΔT.
2. `−0.5` за необратимость — плоский нат, вычтенный из суммы по сущностям: его относительный вес меняется вместе с `|calc|`, а `calc` меняется между `S` и `S'`. `0.5` — приписанная константа, не выведенная.

Альтернатива при приоритете единого ядра — B1, но тогда `ln ψ_opt` не аддитивен, композиция затрат не мультипликативна, и Options-линза выпадает из реестра в натах.

## 9. §4.2 и «безнадёжность»: зависимость от набора опций

### 9.1 Напоминание правила

§4.2 (SKILL.md §3, DOF-SPEC §4.2): сущность включается в `calc` iff она не Collapse Source **и** (`current_dof > 0` ИЛИ (`current_dof == 0` И хотя бы одна доступная опция может поднять её DoF)); исключается только когда `current_dof == 0` И ни одна опция не может его увеличить.

Следствие: **известный ноль без пути восстановления исключается** — значит пассивный объект (камень), у которого `V = 0`, **не получает бесконечного штрафа**. Первоначальное опасение («камень → `−∞`») этим правилом снимается.

### 9.2 Уточнения механики

- Исключение действует на уровне **сущности**; ноль линзы через произведение становится `current_dof = 0` сущности → дальше решает §4.2. Уровни согласованы.
- В реализации `DoF = 0` даёт `ln(max(0, ε)) ≈ −13.8` (конечно, не `−∞`), поэтому даже **оживляемый** ноль не создаёт `NaN`: он конечно тянет индекс, пока его не оживят — это и есть задуманное «не игнорируй спасаемое».

### 9.3 Остаток 1 (важный): «безнадёжность» определяется набором опций, а не миром

Критерий звучит как «**ни одна доступная опция** не может поднять её DoF». «Доступная» = из сгенерированного набора кандидатов, который порождает **Generator** (1–5 опций; в DEEP-режиме — LLM). Значит:

> «нет **предложенного** пути» подменяет собой «нет пути».

Это форма нарушения **Axiom 5** (не предполагать, что неизвестные возможности имеют нулевой DoF) — на уровне опций. И даёт adversarial-стимул: чтобы узел исчез из анализа, достаточно **не сгенерировать** вариант его восстановления. Чем беднее набор кандидатов, тем больше узлов объявляются «безнадёжными» и выпадают.

Фикс (связка с `E`): обосновывать безнадёжность **достижимостью в мире/графе `G`**, а не отсутствием опции в текущем наборе; для исключения требовать машинно-проверяемое свидетельство `no_recovery` (отсутствие пути в `G`), а не «в кандидатах не нашлось». Три статуса из `E` (`reachable` / `proven_unreachable` / `unknown`) применяются здесь напрямую.

### 9.4 Остаток 2: §4.2 становится несущей конструкцией

При `ψ_var = V/(V + V_env)` (см. §10.1) ноль линзы возникает у **каждого** пассивного объекта. Значит масса сущностей приходит с `current_dof = 0` и зависит от правильности классификации §4.2. Ошибка даёт либо `−13.8` (ошибочно сочли оживляемой), либо молчаливое исчезновение из аудита (ошибочно исключили). Поэтому переход `lens-zero → entity-zero → exclusion` должен быть **явным и попадать в отчёт** (§6): иначе не видно, что именно камень «выпал».

## 10. Формула Variety (решено)

### 10.1 Формула и guard

```
ψ_var = 0,                 если V = 0
ψ_var = V / (V + V_env),   иначе
```

- `min(1, ·)` не нужен: `V/(V+V_env) ≤ 1` всегда.
- Guard `V = 0` перехватывает `0/0` **до** деления — поэтому отдельного случая `(0,0)` нет вовсе, есть просто ветка `V = 0`.
- Тело нормировки — **доля**, не порог (см. §10.3).

### 10.2 Определение `V_env` (решено)

`V_env` — **характеристика внешней среды**, а именно разнообразие **внешних возмущений** (Ashby-literal). Следствия:

- посылка `V ⊆ V_env` **не требуется**: тотальность обеспечивает сумма в знаменателе (не деление на `V_env`);
- **две роли среды** различаются: **возмущения** → `V_env` (знаменатель); **аффордансы** (инструменты, инфраструктура) → **`V`** (числитель) через достижимость;
- `V_env = 0` (тихая среда) при `V > 0` даёт `ψ = 1` — «вакуумная» устойчивость, **выводимая** из формулы, а не приписанная вручную.

Таблица случаев:

| `V` | `V_env` | `ψ_var` | Смысл |
|---|---|---|---|
| `> 0` | `> 0` | в `(0,1)` | обычный случай |
| `> 0` | `0` | `1` | среда спокойна ⇒ любого отклика достаточно |
| `0` | `> 0` | `0` | нет векторов отклика ⇒ коллапс (R1) |
| `0` | `0` | `0` | срабатывает ветка `V = 0` (guard) |

### 10.3 Семантика — принято: доля, а не порог

`V/(V+V_env)` — это **доля**, а не проверка неравенства Ashby:

| `V` относительно `V_env` | Формула | Ashby-порог |
|---|---|---|
| `V = V_env` (требование выполнено) | `0.5` | `1` |
| `V ≫ V_env` | `→ 1` (асимптотически) | `1` |
| `V = 0` | `0` | `0` |

То есть «требуемое разнообразие достигнуто» больше не читается как «полная свобода», и `ψ = 1` недостижимо. Это **осознанно принято** — плавная величина вместо признака «достаточно/недостаточно».

### 10.4 Унификация кернела

```
V/(V+V_env) = 1 / (1 + V_env/V)
```

Это **то же ядро `1/(1+x)`**, что предлагалось для Options-линзы (`ψ_opt = 1/(1+c/c₀)`, §2.2), только с `x = V_env/V` вместо `x = c/c₀`. Обе линзы описываются одним семейством профилей, и вопрос `A` сходится с вопросом `B`. Оговорка: для стоимости рекомендовалась экспонента `exp(−c/c₀)` ради аддитивности `ln ψ = −c/c₀`; единое ядро `1/(1+x)` этого лишает (`ln(1/(1+c/c₀))` не линеен). Компромисс «единообразие кернелов ↔ аддитивность штрафа за стоимость» решается в рамках `B`.

**Решено (§8.8, B-iv):** единое ядро **отброшено** в пользу аддитивности, потому что закон композиции обязателен, а ему удовлетворяет только экспонента. Unity линз обеспечивается не алгеброй, а **якорем по оси**: `V = V_env ⇒ ψ_var = 0.5` и `x_g = 0.5 ⇒ f_g = 0.5` — «половина ресурса ⇒ половина свободы». Комбинаторы при этом остаются разными по природе требования: возможности сравниваются с требованием (доля), требования удовлетворяются целиком (произведение по блокам).

### 10.5 Инструменты как фичи состояния (не сущности)

Инструмент (ключ, прибор, инфраструктура) **не моделируется как сущность со своим DoF** и не как ad-hoc «множитель». Он моделируется как **фича состояния/среды**, меняющая граф достижимости `D(S) = (V, E)`:

- «инструмент доступен» — новое различимое состояние (вершина, `V`);
- «воспользоваться инструментом» — доступное действие (ребро, `E`);
- эффект использования открывает **дополнительные рёбра** (новые возможности).

Вклад инструмента виден на обеих осях: state-DoF (`V`) и action-DoF (`ψ_opt`). Инфляция отсекается reachability-критерием (§4): «ключ в кармане» достижим → считается; «ключ на другой планете» → `Δ = 0`. Так инструмент работает **через линзы того, кому он доступен**, — без обнуления произведения и без вопроса об исключении «сущности-инструмента».

### 10.6 Оговорка про пассивные сущности

При произведении линз `ψ_var = 0` (а значит `current_dof = 0`) возникает у любой сущности без векторов отклика. Это разобрано в §9: судьба такого узла решается §4.2 (исключение известного ноля без пути восстановления), а не бесконечным штрафом. Требование к аудиту — видимость пути `lens-zero → entity-zero → exclusion` (§9.4). Отдельно отметим **два смысла `V = 0`**, различимых в отчёте: «отклики были и потеряны» (реальный коллапс) vs «откликов не было никогда» (пассивный объект).
