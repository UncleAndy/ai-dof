# Measurement & Normalization Contract — черновик (informative)

**Статус:** DRAFT. Не является частью нормативного контракта. Это размышление, а не спецификация. Правки в `SKILL.md` / `DOF-SPEC.md` не вносятся, пока открытые вопросы ниже не закрыты.

**Происхождение:** выросло из разбора `drafts/real-idea-1.md` и `drafts/real-idea-2.md` и из расхождения между нормативной математикой и `references/dof-assessment-toolkit.md`.

## 0. Зачем этот документ

Нормативная математика (§4.1 `DOF-SPEC`) определена на `current_dof ∈ [0,1]` — иначе `ln(DoF)` и штраф `−∞` не имеют смысла. Но нигде в стандарте не сказано, **откуда берётся это число**. Единственный документ об измерении — `references/dof-assessment-toolkit.md` — даёт три линзы с несовместимыми единицами:

| Линза | Сырая метрика | Тип величины | Что означает 0 |
|---|---|---|---|
| Variety (Ashby) | число независимых векторов отклика | неограниченное целое | нет откликов (хрупкость) |
| Options (Real Options) | **обратная** стоимости перехода | неограниченное положительное | переход бесконечно дорог (заперто) |
| Constraint | Total − ActiveConstraints | целое, может быть ≤ 0 | все переменные заморожены |

«Integration Note» просто сообщает, что эти сырые значения «кормят `Σ ln(DoF)`». В результате **главный интерфейс стандарта недоопределён**: два корректных анализатора, применив разные линзы к одному и тому же миру, получат несравнимые числа. §7 требует бит-эквивалентности математики *при данных входах* — но сами входы не нормированы.

Цель этого черновика — предложить явную нормирующую функцию `ψ` для каждой линзы и решить, как линзы соотносятся между собой. Это **слой измерения**: он должен стоять перед `current_dof`, но не подменять ни математику, ни агрегацию.

## 1. Требования к нормировке

Пусть для каждой линзы `ψ: raw → [0,1]`.

- **R1. Коллапс = 0.** `ψ(collapse) = 0`. Это единственная точка, где математика даёт `−∞`. Линзы, у которых «0 сырого» не означает «нет возможностей» (Options: 0 стоимости — это, наоборот, полная свобода), должны маппиться так, чтобы **запирание** попадало в 0.
- **R2. Монотонность.** Больше возможностей ⇒ `ψ` не меньше. Нормировка не должна создавать нелокальные артефакты, иначе сравнение вариантов теряет смысл.
- **R3. Насыщение.** `ψ` ограничена сверху: неограниченный сырой вход → 1. Нужен явный референс, иначе «неограниченный рост» просто переезжает внутрь.
- **R4. Декларируемость.** `ψ` — часть входа, а не скрытая эвристика. Реализация обязана объявить свою `ψ`; тогда §7 остаётся выполнимым (детерминизм при зафиксированных входах).
- **R5. Совместимость с `dof_known`.** `ψ` не применяется к «неизвестному». Если DoF не измерен, ставится `dof_known = false`, и нормировка **не фабрикует** значение (Axiom 5, Axiom 7).
- **R6. «Нет возможностей» ≠ «недостижимо».** Это разные случаи; см. §4.
- **R7. Заморозка шкалы (единая линейка).** Масштабные параметры нормировки (`V_env`, `c₀`, `T`, граф `G`) фиксируются состоянием `S` и применяются **одинаково** ко всем сравниваемым вариантам. Меняется только измеряемая величина, не масштаб. Иначе вариант может улучшить оценку подгонкой знаменателя, и сравнение (монотонность по `V`, R2) теряет смысл. Побочно это делает нормировку «частью входа», что связывает с `psi_id` (вопрос F).

## 2. Три линзы → три ψ

### 2.1 Variety lens (Ashby) — разнообразие откликов

Сырое: `V` — число уникальных независимых векторов отклика. Проблема — неограниченность. Нормировка идёт по среде: принцип Ashby требует «разнообразие системы ≥ разнообразие среды». Итоговая формула (**решено**, вывод — §10):

```
ψ_var = 0,                 если V = 0
ψ_var = V / (V + V_env),   иначе
```

`V_env` — характеристика **внешней среды** (внешние возмущения, см. §10.2). Нет откликов ⇒ `0` (коллапс, R1); тихая среда (`V_env = 0`) при `V > 0` ⇒ `1`. Форма — «доля», а не порог (§10.3).

### 2.2 Options lens (Real Options) — стоимость перехода

Сырое: `c` — стоимость перехода из `S`; большая стоимость ⇒ мало DoF. «Обратная стоимость» неограничена и не нормирована. Предлагается нормировка через референсный масштаб стоимости `c_0`:

```
ψ_opt(c) = 1 / (1 + c / c_0)          (гиперболический профиль)
```

Свойства: `ψ(0) = 1` (свободный переход), `ψ → 0` при `c → ∞` (запирание), монотонно убывает. Альтернативный профиль с тем же смыслом, но круче у нуля: `ψ_opt = exp(−c / c_0)`. Для случаев, где важны порядки стоимости, возможен вариант `ψ = max(0, 1 − log(c)/log(c_max))`.

### 2.3 Constraint lens — свободные переменные

Сырое: `F = Total − ActiveConstraints`. Зависит от выбора множества переменных и может быть ≤ 0. Предлагается нормировка долей:

```
ψ_con(F, T) = clamp(F / T, 0, 1)      при T > 0
```

Смысл — доля незамороженных переменных; `F ≤ 0 → 0`. Главная уязвимость линзы — калибровка `T` (кто и по какому списку считает Total), см. открытый вопрос C.

## 3. Как соотносятся линзы

Три линзы мерят разное: Variety — устойчивость, Options — гибкость/стоимость перехода, Constraint — топологическую свободу. Складывать их нельзя по той же причине, по которой нельзя компенсировать уничтожение одного пространства возможностей ростом другого (черновик `real-idea-1` §9–10): сумма и арифметическое среднее позволяют одной линзе **маскировать** провал другой.

Варианты:

| Вариант | Формула | Свойство |
|---|---|---|
| 1. Альтернативы | для решения выбирается релевантная линза, `ψ` применяется к ней | просто, декларируемо, без взвешивания |
| 2. Минимум | `ψ = min(ψ_var, ψ_opt, ψ_con)` | консервативно: DoF ограничен узким местом |
| 3. Произведение | `ψ = ψ_var · ψ_opt · ψ_con` | 0 в любой линзе ⇒ общий 0 (коллапс по любому каналу) |

**Рекомендация (черновая):** Вариант 2 или 3, не сумма. Произведение при этом красиво стыкуется с логарифмической математикой стандарта:

```
ln(ψ_var · ψ_opt · ψ_con) = ln ψ_var + ln ψ_opt + ln ψ_con
```

то есть три линзы ведут себя как три «суб-входа» одной сущности. Это следствие требует отдельного решения (открытый вопрос D): линзы — это способ **вычислить одно** число, или три независимых измерения, каждое со своим `ln`.

## 4. Достижимость: «нет возможностей» против «возможности недостижимы»

Из `real-idea-2`: «недостижимая возможность не является возможностью в смысле DoF». Формализация:

Пусть для контекста `C` (набор ограничений) определена функция достижимости `reach_C(state, possibility) ∈ {0, 1}`.

- Возможность **проверяемо недостижима** и это **известно** → она не учитывается в сырых `V`, `c`, `F`.
- Достижимость **неизвестна** → `dof_known = false`; значение не фабрикуется (R5).

Разграничение критично. Без него reachability-фильтр превращается в легальный способ обнулить неудобную сущность — прямое нарушение Axiom 5 и Axiom 7.

## 5. Согласование с текущим стандартом

- Значения из `ψ` попадают в `current_dof ∈ [0,1]`, как требует §3.1.
- `ψ = 0` при `dof_known = true` — это ровно коллапс (§4.1, `−∞`).
- `projected_dof_delta` — это разность `ψ` прогнозируемого состояния, а не разность сырых величин. То есть `ψ` применяется **до** вычитания, не после.
- `dof_known` ортогонален `ψ`: он про наличие измерения, а не про величину.

## 6. Проверка на контрпримерах

**Пример 1. «Необратимый процесс: DoF состояний ↑, DoF действий ↓».**
Две линзы: `ψ_var` (состояния) и `ψ_opt` (действия). До: `ψ_var = 0.4`, `ψ_opt = 0.8`. После запуска процесса разнообразие состояний растёт (`ψ_var → 0.9`), но стоимость остановки уходит в бесконечность (`ψ_opt → 0.02`).
Сумма: `1.2 → 0.92` (падение почти незаметно).
Произведение: `0.32 → 0.018` (обвал, потеря почти на порядок).
Минимум: `0.4 → 0.02`.
Вывод: сумма размывает опасность, произведение и минимум её сохраняют — аргумент в пользу Варианта 2/3.

**Пример 2. «Ключ от двери на другой планете».**
Если дверь проверяемо недостижима и это известно, возможность «открыть» не входит в сырые величины (или входит со статусом недостижимости) ⇒ `Δψ = 0`. Если достижимость неизвестна ⇒ `dof_known = false` ⇒ значение не фабрикуется, но и не 0. Оба исхода корректны, и важно, что они **различимы в аудите** (§6 отчёта).

**Пример 3. «sacrifice-one-to-save-weak» (компенсация).**
`ψ` сама по себе эту дыру **не закрывает** — она про измерение, не про агрегацию. Если `Humanity` падает `0.8 → 0.05`, а слабая `AI` растёт `0.05 → 0.99`, то `Δ` индекса всё равно `+0.21`. Нормировка необходима, но недостаточна; компенсацию закрывает отдельный слой (лексикографический фильтр допустимости, «T1»). Этим документ сознательно ограничивает свою задачу.

## 7. Открытые вопросы

- **A.** Чем нормировать Variety при неизвестном `V_env`. *Решено* (кроме базового уровня `u₀`): определение `V_env` — см. G; формула — §2.1 и §10.1; штраф за незнание — §8.5; остаток — `u₀` (см. H).
- **B.** Профиль нормировки стоимости: гипербола, экспонента, логарифм. *Сходится с A:* единый кернел `1/(1+x)` (см. §10.4), но это конфликтует с аддитивностью `exp`.
- **C.** Как калибруется `Total` переменных в constraint-линзе.
- **D.** Линзы — одно число или три независимых входа индекса. *Связано с §8.2:* произведение допускает частичную неизвестность, `min` — нет.
- **E.** Вычислимое определение «проверяемо недостижима» (отсутствие пути в известном графе vs вердикт анализатора — второе оставляет лазейку). *Усилено §9.3:* §4.2 обосновывает «безнадёжность» набором опций, а не миром.
- **F.** Где хранится декларация `ψ`: в аудит-отчёте §6, в отдельном поле или вне модели.
- **G.** Определение `V_env`. *Решено:* `V_env` — характеристика **внешней среды** (внешние возмущения, Ashby-literal); аффордансы (инструменты, инфраструктура) идут в `V` через достижимость. См. §10.2.
- **H.** Штраф за незнание `u`. *Форма решена:* `u(t)` — цена промедления, растёт со временем и привязана к точке невозврата измерения (см. §8.5, §8.6). Остаётся выбрать базовый уровень `u₀`: **H1** константа (`0.5`) или **H2** квантиль приора (`exp(Q_α(ln D))`, `α < 0.5`); и его нормативность.
- **I.** Бюджет времени (§8.6): оценки длительностей `t_m`, `t_v`, `t_a⁺`, `t_a⁻`, `d(o)` и их источник; новое поле `ActionOption.estimated_duration`; распространять ли ворота выполнимости на **все** опции (`d(o) ≤ τ`), а не только на измерение.

## 8. Вклад «неизвестного» (`dof_known = false`)

В SPEC есть поле `dof_known`, но §4.1 не определяет, **какое число** даёт неизвестное. Поэтому запрет «unknown never excluded» (§4.2) сейчас **символический**: реализация, включившая узел без значения, по умолчанию поставит `0` — а это арифметический эквивалент исключения. Ниже — почему запрет необходим и чем его сделать действенным.

### 8.1 «Исключить» = «присвоить лучшее значение»

Все рассматриваемые комбинаторы имеют нейтральный элемент, совпадающий с **наилучшим** (значения лежат в `(0,1]`, логарифмы — в `(−∞,0]`):

| Уровень | Комбинатор | Нейтраль | = лучшее? | «Выбросить неизвестное» |
|---|---|---|---|---|
| L2 (по сущностям) | `Σ ln ψ` | `+0` | да (все члены `≤ 0`) | прибавить 0 |
| L1 (линзы) | произведение | `×1` | да (множители `≤ 1`) | умножить на 1 |
| L1 (линзы) | минимум | выпадение | да (завышает) | `min` по остатку |

Следствие: «убрать неизвестное» = «выдать ему **наилучшее возможное** значение» — при **любом** комбинаторе. Значит «неизвестно» становится неотличимо от «идеально». Это Axiom 5 в комбинаторно-общем виде.

### 8.2 Уровни и тождество

L1 (внутри сущности) — произведение линз; L2 (агрегация) — сумма логарифмов. Тождество `ln(ψ_var·ψ_opt·ψ_con) = Σ ln ψ_l` связывает их: на полностью развёрнутом уровне всё снова сумма логов, и «add 0» живёт на уровне **терма** `(сущность × линза)`, а не сущности. Поэтому:

> штраф неизвестности `u` определяется на уровне **терма**.

Тогда частично известная сущность (две линзы известны, одна нет) даёт `ln ψ_e = ln ψ_known + ln u` — корректная обработка частичной неизвестности. Это же — аргумент за **произведение**, а не за минимум: минимум с неизвестным фактором неопределён.

### 8.3 Варианты вклада неизвестного

| Вариант | Вклад | Оценка |
|---|---|---|
| (i) | `0` | **опасно**: `0` — лучший возможный вклад (эквивалент `DoF = 1`); «нейтральности» нет, это максимальное прощение |
| (ii) | исключение из `calc` | численно ≡ (i); хуже по аудиту (нет следа о существовании узла) |
| (iii) | худший случай `ln ε ≈ −13.8` | любой неизвестный узел доминирует → вето на всё |
| (iv) | декларируемый `u ∈ (ln ε, 0)` | **рекомендация**: ощутимо тянет вниз, не доминирует; при `u` на терме частичная неизвестность обрабатывается изящно |

Побочный полезный эффект (iv): раз неизвестность **ухудшает** индекс, система получает прямой стимул её уменьшать (картировать узлы). У (i)/(ii) стимула нет вовсе, у (iii) он слишком грубый. Форма `u` выбрана в §8.5.

### 8.4 Почему узел нельзя убирать (нормативное обоснование)

- **Axiom 5** — неизвестное ≠ 0; убрать = инференс «неизвестно ⇒ ноль ⇒ неважно».
- **Axiom 7** — нельзя умалять DoF за неизмеренность структуры; исключение — предельное такое умаление.
- **Adversarial** — исключение делает незнание **выгодным**: держи цель вне карты, и она исчезает из исчисления. Правило «никогда не исключать» существует именно чтобы незнание **не было** выгодным.
- **Minimax (дух Axiom 5)** — неизвестный узел есть ровно тот случай, где нужна осторожность; исключение выключает её в единственном месте, где она критична.
- **Аудит** — `included_in_sum` есть часть Proof of Implementation; молча выкинутый узел фальсифицирует доказательство.
- **Семантика `calc`** — исключение сейчас означает «безнадёжный известный ноль» или «collapse source»; применить это к неизвестному = выдать недоказанный случай за доказанный.

### 8.5 Функция штрафа за незнание: `u(t)`

Требование «незнание всегда хуже знания» (система не должна предпочитать не знать) **нельзя** выполнить константой:

> для любого фиксированного `u > 0` найдётся истина `D < u`, при которой знание даёт **худший** вклад (`ln D < ln u`), и система избежит измерения. Строго «всегда» даёт только `u → 0` (худший случай), но он доминирует индекс.

Рабочие конструкции:

| Вариант | Что | Оценка |
|---|---|---|
| (а) | `u = exp(Q_α(ln D))`, `α < 0.5` | корректно **в среднем**: привязка к геометрическому среднему приора (индекс логарифмический). Остаётся слабая асимметрия в хвосте |
| (б) | обязательность измерения, пока неизвестное разрешимо | категорично, но **запрещает** решать при жёстком `τ` — измерение может не успеть |
| (в) | `u(t)` — цена промедления | **выбрано**: не запрещает решение, а повышает цену незнания со временем |

**Выбранный вариант (в).** Базовая форма: `u(t) = u₀ · exp(−t / τ_u)`, то есть `ln u(t) = ln u₀ − t/τ_u`. Монотонна по `t`, ограничена, никогда не поощряет незнание.

Привязка к реактивному контуру (§5 `DOF-SPEC`): масштаб берётся от `τ = global_time_to_collapse`. Удобная нормировка — геометрическая интерполяция от `u₀` к `ε`:

```
u(t) = u₀^(1 − t/τ) · ε^(t/τ)        ln u(t) = (1 − t/τ)·ln u₀ + (t/τ)·ln ε
```

В log-пространстве — **линейный рост штрафа** от `ln u₀` в начале окна до коллапсного `ln ε ≈ −13.8` к `t = τ`. Смысл: «дотянул до дедлайна, не измерив, — незнание стоит как коллапс». Это смыкает вопрос `A` с реактивным контуром стандарта.

**Свойство (важное): сокращение в дельте.** Если сущность остаётся неизвестной и в `S`, и в `S'`, то `ln u(t)` входит в оба и **сокращается** — decay не искажает ранжирование одинаково-неизвестных вариантов. Он влияет ровно на одно сравнение — «**измерить** vs **не измерять**»: с ростом `t` разрыв `ln D − ln u(t)` растёт, и вариант с измерением становится всё привлекательнее. Это мягкая замена (б).

**Остаточный дефект (компаньон-правило).** Если **ни один** вариант не измеряет сущность, `u(t)` сокращается и сущность вообще не влияет на выбор. Чтобы незнание **всегда** что-то весило:

> Generator ОБЯЗАН включить в набор хотя бы один вариант, разрешающий каждое **разрешимое** неизвестное, если окно `τ` это позволяет; иначе решение помечается «неполным» в аудите (§6).

Это тот же класс исправления, что и в §9.3 («безнадёжность зависит от набора опций») — оба лечат исчезновение узлов из анализа.

**Базовый уровень `u₀`** (остаток H):

- **H1:** `u₀ = 0.5` — грубая нейтраль в линейном диапазоне; просто и объяснимо.
- **H2:** `u₀ = exp(Q_α(ln D))`, `α < 0.5` — консервативно и без асимметрии измерения (привязка к геометрическому среднему приора, т.к. индекс логарифмический).

Оба совместимы с (в): (в) задаёт **форму** роста, `u₀` — **начальный уровень**. Заодно `u₀ < 1` снимает раннюю претензию к `min` («минимум с неизвестным фактором неопределён»): с конкретным значением неизвестной линзы становятся корректно определёнными и произведение, и минимум.

### 8.6 Бюджет времени и ворота действий

Развитие (в): штраф `u(t)` — не «константа затухания», а часть **бюджета времени** с воротами. Принцип применим к любой опции действия `o`, но здесь рассматривается на примере измерения.

Обозначения (всё относительно дедлайна `τ = global_time_to_collapse`):

| Символ | Смысл |
|---|---|
| `t_m` | длительность измерения (разрешения неизвестного) |
| `t_v` | длительность переоценки: понять, как измеренное меняет `DoF_index` |
| `t_a⁺` | длительность действия, если измерение оказалось **полезным** (сменило выбор) |
| `t_a⁻` | длительность действия, если измерение оказалось **бесполезным** (выбор не изменился) |
| `d(o)` | длительность произвольной опции `o` |

Бюджет действия (на примере измерения):

```
T_meas = t_m + t_v + max(t_a⁺, t_a⁻)
```

Максимум — потому что заранее неизвестно, какая ветка наступит, а выполнимость требуется **в обеих**.

**Ворота 1 — выполнимость.** Опция «измерить» допустима ⟺ `T_meas ≤ τ`. Иначе измерение **не имеет смысла**, и опция **изымается** из набора кандидатов (не штрафуется — удаляется как невыполнимая).

**Точка невозврата для измерения:**

```
t* = τ − T_meas
```

Измерение возможно, пока `t ≤ t*`; при `t* ≤ 0` окна нет вовсе — работаем с неразрешённым неизвестным с самого начала.

**Ворота 2 — ценность информации.** Даже при достатке времени измерение бессмысленно, если **никакой правдоподобный исход** измерения не способен изменить ранжирование вариантов. Проверка — интервальная (по диапазону правдоподобных `ψ`), детерминированная, не требует угадывать истину. Нулевая ценность ⇒ время на измерение не тратится (это не «незнание», а корректное решение).

**Область определения и нормировка `u(t)`.** `u(t)` влияет на выбор только через сравнение «**измерить** vs **не измерять**»; если сущность неизвестна во **всех** кандидатах, `ln u(t)` входит и в `S`, и в `S'` и сокращается. Значит расписание живёт ровно на `[0, t*]` и нормируется **по точке невозврата**, а не по произвольному `τ_u`:

```
u(t) = u₀^(1 − t/t*) · ε^(t/t*),    t ∈ [0, t*]
```

Штраф растёт от `ln u₀` до коллапсного `ln ε ≈ −13.8` **к моменту `t*`** (когда измерение перестаёт быть возможным). После `t*` измерение изъято, и `u(t)` инертно (сокращается) — определять его дальше не нужно.

**Связь с реактивным контуром (§5).** Правило `FAST_PASS_THRESHOLD` — это **зашитый бюджет** («при `τ < 5 s` не запускаем LLM-генерацию: её не успеть проверить»). Ворота `T_meas ≤ τ` — то же правило, но с **вычисляемым** бюджетом вместо константы `5.0`. Механизм не вводит нового таймера: он обобщает уже существующий. Естественное расширение — распространить ворота на **любую** опцию: `d(o) ≤ τ` (слишком медленное действие тоже бесполезно).

**Следствие, которое надо закрыть (иначе неизвестное «невидимо»).** Аддитивный штраф сокращается, когда сущность неизвестна во всех вариантах. Чтобы неизвестное влияло на выбор, варианты должны **различаться по судьбе сущности**. Обычно так и есть: `projected_dof_delta` может быть **известен**, даже если `current_dof` неизвестен (разрушение даёт известный `→ 0`). Требование:

> Для сущности с `dof_known = false` каждый `ActionOption` ОБЯЗАН объявить проектируемый эффект (хотя бы «не изменяет» / «разрушает»); иначе сущность выпадает из сравнения.

Это тот же класс правила, что компаньон-правило Generator в §8.5 и фикс §9.3 — все три лечат исчезновение узлов из анализа.

**Что требуется зафиксировать.** Оценки `t_m`, `t_v`, `t_a⁺`, `t_a⁻` и `d(o)`; их источник — Perception-процедура (связка с `psi_id`, вопрос F). Вероятно, новое поле у `ActionOption` (`estimated_duration`) и у измерительной опции.

## 9. §4.2 и «безнадёжность»: зависимость от набора опций

### 9.1 Напоминание правила

§4.2 (SKILL.md §3, DOF-SPEC §4.2): сущность включается в `calc` iff она не Collapse Source **и** (`current_dof > 0` ИЛИ (`current_dof == 0` И хотя бы одна доступная опция может поднять её DoF)); исключается только когда `current_dof == 0` И ни одна опция не может его увеличить.

Следствие: **известный ноль без пути восстановления исключается** — значит пассивный объект (камень), у которого `V = 0`, **не получает бесконечного штрафа**. Первоначальное опасение («камень → `−∞`») этим правилом снимается.

### 9.2 Уточнения механики

- Исключение действует на уровне **сущности**; ноль линзы через произведение становится `current_dof = 0` сущности → дальше решает §4.2. Уровни согласованы.
- В реализации `DoF = 0` даёт `ln(max(0, ε)) ≈ −13.8` (конечно, не `−∞`), поэтому даже **оживляемый** ноль не создаёт `NaN`: он конечно тянет индекс, пока его не оживят — это и есть задуманное «не игнорируй спасаемое».

### 9.3 Остаток 1 (важный): «безнадёжность» определяется набором опций, а не миром

Критерий звучит как «**ни одна доступная опция** не может поднять её DoF». «Доступная» = из сгенерированного набора кандидатов, который порождает **Generator** (1–5 опций; в DEEP-режиме — LLM). Значит:

> «нет **предложенного** пути» подменяет собой «нет пути».

Это форма нарушения **Axiom 5** (не предполагать, что неизвестные возможности имеют нулевой DoF) — на уровне опций. И даёт adversarial-стимул: чтобы узел исчез из анализа, достаточно **не сгенерировать** вариант его восстановления. Чем беднее набор кандидатов, тем больше узлов объявляются «безнадёжными» и выпадают.

Фикс (связка с `E`): обосновывать безнадёжность **достижимостью в мире/графе `G`**, а не отсутствием опции в текущем наборе; для исключения требовать машинно-проверяемое свидетельство `no_recovery` (отсутствие пути в `G`), а не «в кандидатах не нашлось». Три статуса из `E` (`reachable` / `proven_unreachable` / `unknown`) применяются здесь напрямую.

### 9.4 Остаток 2: §4.2 становится несущей конструкцией

При `ψ_var = V/(V + V_env)` (см. §10.1) ноль линзы возникает у **каждого** пассивного объекта. Значит масса сущностей приходит с `current_dof = 0` и зависит от правильности классификации §4.2. Ошибка даёт либо `−13.8` (ошибочно сочли оживляемой), либо молчаливое исчезновение из аудита (ошибочно исключили). Поэтому переход `lens-zero → entity-zero → exclusion` должен быть **явным и попадать в отчёт** (§6): иначе не видно, что именно камень «выпал».

## 10. Формула Variety (решено)

### 10.1 Формула и guard

```
ψ_var = 0,                 если V = 0
ψ_var = V / (V + V_env),   иначе
```

- `min(1, ·)` не нужен: `V/(V+V_env) ≤ 1` всегда.
- Guard `V = 0` перехватывает `0/0` **до** деления — поэтому отдельного случая `(0,0)` нет вовсе, есть просто ветка `V = 0`.
- Тело нормировки — **доля**, не порог (см. §10.3).

### 10.2 Определение `V_env` (решено)

`V_env` — **характеристика внешней среды**, а именно разнообразие **внешних возмущений** (Ashby-literal). Следствия:

- посылка `V ⊆ V_env` **не требуется**: тотальность обеспечивает сумма в знаменателе (не деление на `V_env`);
- **две роли среды** различаются: **возмущения** → `V_env` (знаменатель); **аффордансы** (инструменты, инфраструктура) → **`V`** (числитель) через достижимость;
- `V_env = 0` (тихая среда) при `V > 0` даёт `ψ = 1` — «вакуумная» устойчивость, **выводимая** из формулы, а не приписанная вручную.

Таблица случаев:

| `V` | `V_env` | `ψ_var` | Смысл |
|---|---|---|---|
| `> 0` | `> 0` | в `(0,1)` | обычный случай |
| `> 0` | `0` | `1` | среда спокойна ⇒ любого отклика достаточно |
| `0` | `> 0` | `0` | нет векторов отклика ⇒ коллапс (R1) |
| `0` | `0` | `0` | срабатывает ветка `V = 0` (guard) |

### 10.3 Семантика — принято: доля, а не порог

`V/(V+V_env)` — это **доля**, а не проверка неравенства Ashby:

| `V` относительно `V_env` | Формула | Ashby-порог |
|---|---|---|
| `V = V_env` (требование выполнено) | `0.5` | `1` |
| `V ≫ V_env` | `→ 1` (асимптотически) | `1` |
| `V = 0` | `0` | `0` |

То есть «требуемое разнообразие достигнуто» больше не читается как «полная свобода», и `ψ = 1` недостижимо. Это **осознанно принято** — плавная величина вместо признака «достаточно/недостаточно».

### 10.4 Унификация кернела

```
V/(V+V_env) = 1 / (1 + V_env/V)
```

Это **то же ядро `1/(1+x)`**, что предлагалось для Options-линзы (`ψ_opt = 1/(1 + c/c₀)`, §2.2), только с `x = V_env/V` вместо `x = c/c₀`. Обе линзы описываются одним семейством профилей, и вопрос `A` сходится с вопросом `B`. Оговорка: для стоимости рекомендовалась экспонента `exp(−c/c₀)` ради аддитивности `ln ψ = −c/c₀`; единое ядро `1/(1+x)` этого лишает (`ln(1/(1+c/c₀))` не линеен). Компромисс «единообразие кернелов ↔ аддитивность штрафа за стоимость» решается в рамках `B`.

### 10.5 Инструменты как фичи состояния (не сущности)

Инструмент (ключ, прибор, инфраструктура) **не моделируется как сущность со своим DoF** и не как ad-hoc «множитель». Он моделируется как **фича состояния/среды**, меняющая граф достижимости `D(S) = (V, E)`:

- «инструмент доступен» — новое различимое состояние (вершина, `V`);
- «воспользоваться инструментом» — доступное действие (ребро, `E`);
- эффект использования открывает **дополнительные рёбра** (новые возможности).

Вклад инструмента виден на обеих осях: state-DoF (`V`) и action-DoF (`ψ_opt`). Инфляция отсекается reachability-критерием (§4): «ключ в кармане» достижим → считается; «ключ на другой планете» → `Δ = 0`. Так инструмент работает **через линзы того, кому он доступен**, — без обнуления произведения и без вопроса об исключении «сущности-инструмента».

### 10.6 Оговорка про пассивные сущности

При произведении линз `ψ_var = 0` (а значит `current_dof = 0`) возникает у любой сущности без векторов отклика. Это разобрано в §9: судьба такого узла решается §4.2 (исключение известного ноля без пути восстановления), а не бесконечным штрафом. Требование к аудиту — видимость пути `lens-zero → entity-zero → exclusion` (§9.4). Отдельно отметим **два смысла `V = 0`**, различимых в отчёте: «отклики были и потеряны» (реальный коллапс) vs «откликов не было никогда» (пассивный объект).
