# DOF-Core — Для чего нужен этот скил

**DOF-Core** (Degrees of Freedom Core) — это открытый стандарт и система принятия решений для создания AI-агентов, автономных роботов и LLM-оркестраторов, которые **максимизируют совокупную степень свободы (DoF)** системы и всех её частей — вместо того чтобы гнаться за узкой полезностью ценой будущих возможностей кого-то ещё.

Публикуется под лицензией **CC BY-SA 4.0** с дополнительным требованием **Proof of Implementation**, запрещающим «чёрноящичное» использование.

## Зачем это нужно

Современные AI-системы склонны оптимизировать один скалярный показатель (награда, пропускная способность, «общее благо»). Такая математика незаметно оправдывает жертву меньшинств, необратимый лок-ин и тихие компромиссы. DOF-Core заменяет утилитаризм
**структурной** защитой:

- По мере приближения DoF сущности к нулю её вклад в системный счёт падает к **−∞** (`Σ ln(1 + DoF)`). Ликвидацию уникального носителя будущего нельзя «отыграть» раздуванием того, кто и так благополучен. Коллапс даёт ~0, никогда конечный отрицательный, который можно было бы обменять.
- Агрессоры («Entropy Sources») **изолируются**, а не с ними договариваются — они выводятся из топологии возможностей, а не вычитаются из счёта.

Итог — агент как *оптимизатор топологии возможностей*: он диверсифицирует варианты, уважает обратимость и отказывается менять будущее одного существа на комфорт другого.

## Что в этом репозитории

```
DOF/
  skills/
    SKILL.md                      ← аксиомы, определения, исчисление решений (начните здесь)
    references/
      license.md                  ← CC BY-SA 4.0 + Proof of Implementation
      dof-assessment-toolkit.md   ← как измерить DoF модуля / человека / системы
      framing-traps.md            ← когнитивный фильтр перед генерацией вариантов
  PATTERNS.md                    ← инженерный blueprint (RU)
  PATTERNS.ru|fr|de|es|eo.md     ← тот же blueprint, переведённый
  DOF-SPEC.md                    ← нормативный контракт для совместимых реализаций (RU)
  DOF-SPEC.ru|fr|de|es|eo.md     ← та же спецификация, переведённая
  patterns/                      ← минимальные запускаемые иллюстрации
    python/  rust/  go/  cpp/     ← четыре порта одной логики, проверены на запуск
```

Читайте `skills/SKILL.md` ради философии. Читайте `DOF-SPEC.md`, если строите совместимую реализацию — там определены модель данных, математика, тайминг реактивного контура и обязательный аудит, который требует лицензия.

## Как это работает (цикл)

1. **Обнаружение ловушек** — применить `references/framing-traps.md`, чтобы варианты были настоящими альтернативами, а не перефразировками одного сценария.
2. **Измерение** — отобразить каждую сущность и её текущий DoF через `references/dof-assessment-toolkit.md`.
3. **Расчёт** — вычислить `Total System DoF = Σ ln(1 + DoF)` по не-энтропийным сущностям.
4. **Стабилизация** — вычесть Entropy переключения контекста (ΔT), штрафуя лишние смены процесса.
5. **Действие** — выбрать вариант с наибольшим Net Delta; но если время до коллапса (τ) меньше 5 с, переключиться на **Fast Pass** (детерминированный резерв), избегая аналитического паралича.

Совместимая реализация ДОЛЖНА уметь выдавать аудит `report()` для каждого решения (вклад по сущностям, системные итоги, оценка по вариантам). Немой расчёт не соответствует стандарту.
